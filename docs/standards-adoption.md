# Standards adoption

`docs/standards.md` is a playbook distilled from a prior commerce-focused Coveo project. It's explicitly generalized, not everything in it fits a take-home search assessment — several patterns exist to protect secrets and privileged server routes in an app that took payments/PII. This project's Coveo Headless SDK calls the Search API directly from the browser using a public search token by design, so there's no server-held secret to protect or rate-limit. Adopting those patterns anyway would be cargo-culting.

This doc records what was adopted as-is, adapted for this project's scale, or explicitly skipped — and why. It doubles as backing material for the Topic 1 panel presentation's "why did you choose this architecture" question.

| # | Section | Decision | Why |
|---|---|---|---|
| 1 | Repo & commit hygiene | Adapt — lightweight `.githooks/pre-commit` (lint + typecheck + a test-coverage guard, `scripts/check-test-coverage.mjs`, that blocks a commit touching `src/coveo/*` or `src/app/api/*/route.ts` without a mirrored test under `tests/unit/coveo/` or `tests/unit/app/api/`) | Single-contributor take-home; a 3-tier hook system (pre-commit/commit-msg/pre-push) is more process than the project needs, but a cheap pre-commit gate — including "don't let untested logic slip in" — is free insurance |
| 2 | Environment & config loading | Adopt — one `resolveCoveoConfig()` function, not `process.env` read ad hoc | Keeps the "is Coveo configured" check and the actual values sourced from a single place |
| 3 | Feature flags | Skip | No flag-gated behavior exists in this app |
| 4 | Security boundary | Adapt — security headers (CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy) in `next.config.ts`. Skip secret redaction | Headers are cheap and real value once publicly hosted; redaction has nothing to redact — the Coveo token here is a public search token, deliberately client-visible by Coveo's own architecture |
| 5 | Rate limiting | Skip | No privileged server route exists — Headless calls Coveo directly from the browser; Coveo's platform does its own throttling |
| 6 | Client state & handoff | Skip | The detail page (`src/app/pokemon/[name]/page.tsx`) already re-queries by name on load — a server-authoritative-style lookup, so a shared link works cold without any client-side handoff cache |
| 7 | Timeouts & resilience | Adapt — no custom fetch/timeout wrapper (Headless owns its HTTP layer, treated as a black box per §9); adopt the stated behaviors: a user-triggered retry action in error states, explicitly no automatic retry-with-backoff | Wrapping the SDK's internal fetch would fight it, not extend it |
| 8 | Error typing & logging | Adopt — `ApplicationError` (`code`, `message`, `userMessage`, `recoverable`) normalized from Headless's `state.hasError` | Distinguishes "Coveo returned an error" from "query just has zero results," which the UI previously conflated |
| 9 | Isolating logic from UI | Adopt, documented — this repo has two lanes, not three: Domain SDK (Headless controllers in `src/coveo/`) and UI (React state in components). No server lane exists because no call needs a privileged credential — the search token is meant to be public | Explains the intentional absence of a server layer rather than leaving it as an unstated gap |
| 10 | Mapper boundary | Adopt — `src/coveo/mapPokemonResult.ts` converts a Headless `Result` to a local `PokemonItem` once | Components previously reached into `result.raw[POKEMON_FIELDS.image]` directly; a field rename meant editing every component instead of one function |
| 11 | Types & interfaces | Adopt — discriminated union render state (`{status: "loading" \| "empty" \| "error" \| "success"}`) replacing independent `isLoading`/`results.length === 0` checks | Removes an impossible-state gap (e.g. stale results rendering during a subsequent load) |
| 12 | Unit & e2e testing | Adapt — tests live under `tests/` (`tests/unit/` for Vitest, `tests/e2e/` for Playwright — not colocated with source); unit-test coverage scope is `src/coveo/*` plus `src/app/api/*/route.ts` (server-side logic — mappers, config, and now the token/passages route handlers), see `vitest.config.mts`; Playwright covers `tests/e2e/unconfigured.spec.ts` (permanent smoke suite for the no-org state) plus `tests/e2e/search.spec.ts` and `tests/e2e/ask-about-pokemon.spec.ts` (configured golden paths, `test.skip`-gated on `NEXT_PUBLIC_COVEO_ORGANIZATION_ID`) | Can't meaningfully e2e-test the golden path against a live Coveo org until access lands; the harness and true assertions exist now, gated to run for real once the org is configured (which it now is) |
| 12b | Component unit testing | Adapt — grew the project a jsdom/testing-library harness (`@testing-library/react`, `@testing-library/jest-dom`; `vitest.config.mts`'s `test.projects` now runs a `node` project for the existing `tests/unit/**/*.test.ts` suite unchanged, plus a `jsdom` project whose `include` covers `tests/unit/components/**/*.test.tsx` and, as a second explicit glob entry, `tests/unit/coveo/useControllerState.test.tsx` — a hook test, not a component, but it needs `renderHook`'s DOM environment the same way component tests do, so it rides the jsdom project rather than getting a third one — sharing a setup file at `tests/unit/setup-jsdom.ts`) once the component count justified it; scope is named explicitly, same philosophy as #12's coverage list — only components with real logic (state, computed values, conditionals, URL/localStorage sync) get a test: `Tabs`, `SearchUrlSync`, `CompareProvider`, `CompareTray`, `StatBar`, `Chip`, `Pager`, `PokemonMarkdown`, `Breadcrumb`, `TypeDefenses`, `EvolutionChain`, `DidYouMean`, `FacetSpeed`, `BrowseByType`. Pure presentational components (props straight to JSX, no branching) stay untested — `CoveoConfigBanner`, `FacetGeneration`, `FacetRail`, `TrainingPanel`, `AbilityList`, `AppHeader`, `PokemonHero`, `PokemonProfilePanel`, `PokemonStatPanel`, `DataList`, `ConfigRequiredDialog`, `FacetAbilities`, `FacetType`, and any Headless-controller-only wrapper in the same shape | One component's worth of state-machine logic used to be the bar for skipping a harness entirely (see prior wording of #12); once ~14 components carried real logic, the harness paid for itself. Blanket component coverage would test JSX structure, which is what e2e already exercises against a real org |
| 13 | Documentation | Adopt — `docs/adr/` for decisions already made | Direct fit for the Topic 1 "why this architecture" prompt |
| 14 | Lessons from the log | Adopt as habit — "degrade to a handled error state, never crash on missing config" is already implemented (`CoveoConfigBanner`) | No new file needed, just continuing the habit as new integration points are added |
